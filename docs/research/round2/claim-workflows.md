# Comparing quantum resource claims: existing tools and user requests

Research date: **2026-10-23**. Decision support, not a product selection. Prior reports read: `resource-claims-verification.md` (full), `build/competitors-users.md` (main findings and evidence), `decision/ranked-memo.md` (full), `build/demo-fact-check.md` (full), and the research brief. URLs below are primary sources inspected this round; source dates/read depths are in §7. No messages sent, code executed, tests run, or production implementation changed.

## 1. Bottom line

- **Kill the premise that a stand-alone quote-backed refusal app has demonstrated demand.** There are observed jobs—maintain an estimate table, explain architecture assumptions, disclose approximation, reproduce a counterexample—but no inspected practitioner explicitly requests a new two-card refusal website. Quotes/refusals are useful implementation features, not a validated user job.
- **Keep a small exportable evidence contribution as a hypothesis.** PQS explicitly welcomes corrections; Jaques explicitly asks for help finding papers and a more precise assumption taxonomy; ECDSA participants explicitly request visible approximation evidence and a retained fixed-input regression. These existing destinations are more credible than acquiring a new app habit.
- **The strongest new demand evidence is ECDSA.Fail issues [#239](https://github.com/Layr-Labs/ecdsafail-challenge/issues/239), [#284](https://github.com/Layr-Labs/ecdsafail-challenge/issues/284), and [#131](https://github.com/Layr-Labs/ecdsafail-challenge/issues/131), not disagreement among news trackers.** They contain requests and public corrections, not merely hypothetical confusion. They favor an upstream diagnostic/disclosure contribution; they do not establish a paying user.
- **HashSmash is more implemented than the old “Exact harness TBD” quotation implies.** Current source has typed claims, paired AI review, bounded experiments, immutable evidence bindings and a Pareto adapter; the live page displays AI- and human-reviewed results. Its source publication, configured admission and live activation are explicitly separate. Do not infer deployment of every local feature from a README or infer a gap from an old vision doc.
- **Do not call every numerical disagreement an error.** PQS's Gidney “1,537” and Table 5's “1,399” describe different accounting contexts in the same paper. A quote can perfectly match a number while the associated semantic label is wrong.
- **Conditional preference within this slice:** evidence-pack integration first; narrowly scoped regression/disclosure integration if Gautham confirms the open request still matters; stand-alone Ledger only if a practitioner supplies a next real comparison and wants the recurring workflow. Lack of reply remains unknown, not rejection.

**One task not adequately completed by the inspected public default surfaces:** “Beside this exact current ECDSA baseline, distinguish its official selected-support acceptance from known fixed-input failures and fresh-corpus evidence, preserve the regression, and make the approximation policy legible.” #239 and #284 explicitly ask for it; README still says hash-derived inputs mean “you cannot tune the circuit against the test set,” whereas the maintainer explicitly permits nonce hunting. Participants currently assemble the evidence manually. Existing code *can* perform custom runs; the gap is a maintained evidence/report workflow, not missing simulation capability. ## 3. Recurring discrepancies and actual correction requests

### A. Selected-support acceptance versus approximation policy: repeated requests, real users

1. **June 3–15: [#1](https://github.com/Layr-Labs/ecdsafail-challenge/issues/1), willzeng; maintainer gpsanant.** User asks whether reroll knobs are within the benchmark's spirit. [Maintainer response](https://github.com/Layr-Labs/ecdsafail-challenge/issues/1#issuecomment-4704742480): “The only guarantee we're going for is that the circuit is 99% correct” and “Nonce hunting is not an algorithmic improvement.” This is an explicit policy explanation, not evidence that the 9,024 tests prove universal correctness. The README's “cannot tune” and “There are no loopholes” wording is too broad if detached from this explanation.
2. **Aug 25–Sept 9: [#131](https://github.com/Layr-Labs/ecdsafail-challenge/issues/131), odinfree and tarekeleter.** Original author says an autonomous submission reduced a round budget, improving score while increasing expected failed shots and subsequent search cost; requests human consideration and offers rollback. Crucially, the author's [correction](https://github.com/Layr-Labs/ecdsafail-challenge/issues/131#issuecomment-5414501894) says the source was not “poisoned”: parameters can be restored; the score bar moved. A second participant [corroborates the tradeoff on another baseline](https://github.com/Layr-Labs/ecdsafail-challenge/issues/131#issuecomment-5610431826) and discloses the same omission in their own recommendations. Measurements are participant-reported, not reproduced here. A ledger that quotes only the apology would perpetuate a corrected claim.
3. **Sept 8: [#239](https://github.com/Layr-Labs/ecdsafail-challenge/issues/239), bulengerk.** Supplies coordinates, pinned source `708d5674…`, expected and observed outputs, native reproduction and independent arithmetic checks. Explicit ask: “retain this fixed-input regression” and show approximation/error-budget evidence beside baselines. It carefully states one counterexample does **not** violate the declared 99% target, estimate a population failure rate, prove phase behavior, or establish hosted-artifact byte identity.
4. **Sept 9: [#284](https://github.com/Layr-Labs/ecdsafail-challenge/issues/284), tarekeleter.** Repeats explicit documentation request and asks to enable Discussions or designate issues as the research home. Corrects the mechanism attribution of an improvement, while saying the headline cost was independently reproduced. Describes paired circuit-independent frozen input draws; existing practitioners already know how to build this instrument.

**Meaning:** observed pain is repeatedly recovering context and paying for omitted uncertainty, policy and provenance. No maintainer acceptance of a new third-party tool was observed. Most diagnostic content is agent-assisted; public activity is not equivalent to distinct commercial customers.

### B. Logical width to physical savings: a real public rebuttal, already done

[Ivezic, Oct 14/17](https://postquantum.com/security-pqc/ecdsa-fail-low-qubit-circuit/) quotes [Dallaire-Demers' Oct 13 post](https://x.com/dallairedemers/status/2110068442330234929) saying 893 logical qubits shaves physical requirements by 25%. Ivezic explains why lookup, memory-code block sizes, factories and runtime matter. He does **not** simply reject 25% everywhere: his conditional IonQ scaling is 27–29% fewer ions but longer runtime; Oratomic at most16%; Google requires recompilation. These are the analyst's conditional calculations, not vendor-updated estimates. This round read the entire rebuttal, not the original X page; the repository fact-check previously independently retrieved the post. It is evidence of a useful expert job, not an unanswered correction request or proven recurring app demand.

### C. Two perfectly quoted Gidney widths are not interchangeable

[Gidney §3.1/Table5](https://arxiv.org/html/2505.15917v1#S3.T5) reports **1,399** logical qubits; [§3.2](https://arxiv.org/html/2505.15917v1#S3.SS2) explicitly reports **1,537 including idle hot patches** for its layout. PQS uses1,537; Ivezic's scorecard uses1,399. Both numbers appear in the primary source. Correct workflow: retain separate typed accounting contexts, and flag the paper's internal tallies for expert resolution where needed; do not silently “correct” one from the other. Table5's6.5B Toffolis is **expected per factoring, not per shot**. A model quoting6.5B correctly can still mislabel its unit. This is a stronger semantic test than finding an exact source span.

Jaques' methodology prose prints a fit constant `T=0.1225`; the linked code has `SURFACE_CODE_T = 0.01225`. Observed transcription difference, **not a diagnosed code bug**; no execution or correction request made. A useful upstream evidence contribution would ask which expression is intended, rather than autonomously changing the estimate.

## 4. What source anchoring does and does not buy

Exact span checks prove text provenance only. They do not establish that a number is an upper bound versus achieved cost; a per-shot quantity versus expected total; the selected operating point; a classical output test versus coherent algorithm success; live hardware versus an architectural assumption; or a current claim versus an author's corrected earlier claim. Even deterministic gates depend on human-reviewed typing. “Unknown” is different from “incompatible,” and architectural differences can still support an explicitly conditional comparison. No paper or tool here licenses an automatic physical-savings inference.

## 5. Three genuine variants, including rejection criteria

### Variant A — Stand-alone pair-comparison/refusal workbench: **do not select by default**

- **User/job/input/output:** specialist analyst comparing two pinned published operating points; inputs are selected records plus a specific proposed ratio; output is a sourced comparison, conflicts/unknowns and a downloadable record.
- **Smallest complete12h artifact [INFERENCE]:** four reviewed operating-point records, two supported comparisons and two unsupported claims; one real source-grounded extraction draft; explicit field/operating-point review; static deployment/export. No arbitrary PDFs, monitoring, forecast or physical conversion.
- **Existing comparison/demand:** PQS serves discovery, Ivezic serves explanation, paper Table3 serves circuit comparison. No direct request for this app observed. AI can draft semantic fields, but a normal coding agent with the same sources can do a single comparison. Recurring structured export/review must be the advantage, measured rather than asserted.
- **Data/licence/compute:** PQS CSV CC BY4.0; Gidney/ECDSA paper HTML CC BY4.0; CPU and a small metered model call. Do not copy restricted hosted data or entire articles. [$5–15 initial model allowance is an estimate, not a measured bill.]
- **Cheap deciding experiment:** give Ivezic or Jaques a one-page record and ask for the next real comparison; observe whether they reuse/export it and whether reviewing AI fields takes less effort than doing the comparison directly. An attractive demo alone does not pass.
- **Adoption path:** link from existing analyst publication or source-data workflow, without a new account. **Reject:** no next task, no recurring reuse, or expert review dominates savings. Strongest reason to kill: expert prose plus existing CSV already suffices.

### Variant B — Exportable assumptions/correction evidence pack: **keep as contribution hypothesis**

- **User/job/input/output:** PQS maintainer or Jaques maintaining their own publication; input one paper/version and existing row; output a reviewable CSV/JSON patch plus short evidence note separating layout/logical accounting, bound operators, runtime/operating point, assumptions and unresolved source inconsistencies.
- **Observed ask:** PQS welcomes corrections; Jaques requests paper leads and a precise assumptions taxonomy. His taxonomy/postdoc statement does not mean a weekend pack fulfills the research program. Frequency: yearly updates/paper discovery explicitly mentioned, not daily paid work.
- **Smallest complete12h artifact [INFERENCE]:** one Gidney pack and one ECDSA policy/validation pack, each with pinned citations, proposed destination-compatible fields, reviewer dispositions and a simple readable/exportable view. One complete pack is preferable to20 shallow cards. Optional static diff feed only after the destination accepts the format.
- **Existing comparison:** extends rather than duplicates PQS CSV; complements Jaques' code/chart; no need to copy HashSmash review infrastructure. AI drafts candidate mappings/diffs; plain code handles exact arithmetic/version/operator preservation; human approves semantics. Test against a same-source coding-agent draft, not a knowledge quiz.
- **Data/licence/compute:** same CC BY corpus, self-authored annotations and short attributed quotes. CPU; bounded API allowance as above. Jaques script lacks an inspected reuse licence: link it, do not vendor it.
- **Cheap deciding experiment:** send a **specific patchable record**, not “would you like an AI tool?” Ask whether a maintainer will incorporate it or specifies their required fields. Success is accepted correction/data format or a requested next pack, not polite interest.
- **Adoption path:** maintainer's current CSV, chart-source data or publication correction channel. **Reject:** contributors already have all fields, disagree with abstraction, or only need a one-off typo correction. Strongest reason against a product: this may be a valuable afternoon contribution rather than a business or durable app.

### Variant C — Pinned-baseline regression + approximation disclosure report: **strongest explicit ask, integrate only**

- **User/job/input/output:** ECDSA maintainer reviewing a known baseline, and participants assessing what “accepted” means. Inputs: pinned source/artifact identity, published fixed witness and organizer-approved fresh seeds; output: separate official status, regression observations, holdout sample/error channels, provenance and limitations. Never an alternative official score or universal certificate.
- **Demand/existing solution:** #239 asks for regression retention and visible evidence; #284 repeats policy request; #131 demonstrates recurring omitted tradeoff and correction. However paper §5.4 already reevaluates42 circuits on50,000 common inputs, and participants have paired instruments. Improve that workflow, do not announce a novel regrader.
- **Smallest complete12h artifact [INFERENCE]:** package the published fixed witness as an isolated pinned-source diagnostic, emit one honest machine-readable report and human-readable baseline appendix; add a bounded small fresh-corpus run only if requested and affordable. Do not promise100k inputs across multiple circuits in12h; wall time/memory unmeasured. Stop on unavailable prerequisite rather than fabricate a certificate. No circuit improvements, nonce searching or automatic submission.
- **Data/licence/compute:** public fixture attribution/permission; ECDSA terms §5 assert MIT for repository harness and Apache2.0 for promoted contributions, but API metadata reports no detected licence. Confirm applicable file notices before reuse. Local Rust CPU/isolated process; no GPU required for the fixed witness. CPU cost for a larger corpus remains unmeasured. Hosted API is not a general-use data licence.
- **AI contribution:** small: draft notes, identify missing fields and summarize diffs. Simulator and independent arithmetic do the checking. A plain coding agent can implement the fixture; useful credibility would come from upstream acceptance and accurate experimental scope, not an AI claim. Weak as an AI-first hackathon centerpiece.
- **Cheap deciding experiment:** ask Gautham whether #239 is still actionable and whether he would merge/use this report; parent can then exercise the public fixed witness. Only real run receipts support outcome claims.
- **Adoption path:** maintainer-reviewed upstream regression/disclosure, outside the protected solver submission surface. Terms forbid modifying protected infrastructure *as a challenge submission*; get organizer direction for an infrastructure contribution. **Reject:** already handled, maintainer declines policy/report changes, or source/artifact/licence boundary cannot be resolved. Strongest rejection: existing community instruments already solve execution; remaining work is governance/documentation rather than a new tool.
